1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
AegisStream is an enterprise-grade, distributed stream processing platform 
designed to detect real-time UPI mule accounts and multi-hop money laundering 
chains at millisecond latency.

The Core Problem:
In modern instant payment rails like UPI (Unified Payments Interface), money 
mule networks use automated bots and compromised accounts to rapidly forward 
illicit funds through intermediate accounts. A victim transfers funds to Account 
A, which within 2 to 5 seconds transfers to Account B, which within another 
2 seconds forwards to Account C, and finally to Account D for cash-out. 
Conventional rule-based batch systems run nightly or hourly, long after the 
money has left the banking network.

The AegisStream Solution:
AegisStream intercepts pass-through velocity at wire speed:
- An account is identified as a suspicious mule node if incoming funds are 
  forwarded out within a strict threshold of <= 15.0 seconds (Delta t <= 15s).
- The pipeline captures and reconstructs multi-hop chains of 3, 4, and 5+ hops.
- Built on a decoupled 5-tier architecture: Python/Kafka Ingestion -> Apache 
  Flink 1.18 Stateful Stream Engine -> ClickHouse Columnar OLAP -> FastAPI 
  Backend Service -> React 18 Cinematic UI Dashboard.

4.1 INGESTION SERVICE: producer/
--------------------------------------------------------------------------------
Files:
- producer/simulator.py:
  * Reads the CSV dataset from `Merged_corrected_final.csv`.
  * Filters out all rows with status != 'SUCCESS' so only valid transfers enter.
  * Connects to Kafka broker at `kafka:9092` via `confluent-kafka.Producer`.
  * Emits transactions at `PACING_INTERVAL_SEC = 0.2` (5 transactions per second).
  * Overrides the static 2024 timestamp with `datetime.now(timezone.utc)` so that
    Apache Flink's event-time watermarking logic operates in real time without lag.
  * Injects synthetic multi-hop mule chains every 75 transactions (and at #15):
    Hop 1: User A -> User B (₹50,000.00, 0s delay)
    Hop 2: User B -> User C (₹47,500.00, 2s delay, -5% layering fee)
    Hop 3: User C -> User D (₹45,125.00, 2s delay, -5% layering fee)
  * Uses realistic 10-digit VPAs (e.g. `9845021431@okaxis`) and authentic names.
  * Uses `admin_client.create_topics()` to verify topic `upi.transactions.raw` exists.

- producer/Merged_corrected_final.csv:
  * Contains 190,010 real UPI transactions across major Indian banks and cities.
  * Columns: transaction_id, timestamp, sender_name, sender_vpa, receiver_name,
    receiver_vpa, amount, status, bank_code, location.
  * Analysis shows the dataset naturally contains 280 2-hop, 280 3-hop, 192 4-hop,
    and 86 5-hop chains in addition to the synthetic injected chains.

- producer/Dockerfile:
  * Base image: `python:3.10-slim`.
  * Installs `confluent-kafka` and `pandas` from `requirements.txt`.
  * Runs `python simulator.py` on container startup.

4.2 STREAM PROCESSING ENGINE: flink-job/
--------------------------------------------------------------------------------
Files:
- flink-job/pom.xml:
  * Configures Apache Maven build with Java 11 target.
  * Includes `flink-streaming-java`, `flink-clients`, `flink-connector-kafka`,
    `flink-connector-jdbc`, `clickhouse-jdbc` driver, and Jackson JSON mapper.
  * Uses `maven-shade-plugin` to build a self-contained fat JAR (`flink-job-1.0.0.jar`).

- flink-job/src/main/java/com/mule/detector/MuleDetectorJob.java:
  * The main Flink streaming pipeline definition.
  * Configures checkpoints every 10 seconds for fault-tolerant state recovery.
  * Creates `KafkaSource<Transaction>` reading from `upi.transactions.raw`.
  * Assigns bounded out-of-orderness watermarks (`Duration.ofSeconds(3)`).
  * SINK 1: Writes EVERY transaction directly into ClickHouse `raw_transactions`
    table via a batch `JdbcSink` (batch size 20 or 100ms interval).
  * FlatMap Account Perspective Mapper:
    Duplicates each transaction into two perspectives:
    1. INCOMING perspective for `receiver_vpa` (accountId = receiver_vpa).
    2. OUTGOING perspective for `sender_vpa` (accountId = sender_vpa).
  * Keys the stream by `Transaction::getAccountId` and invokes `PassThroughDetector`.
  * SINK 2: Writes flagged `Alert` records into ClickHouse `fraud_alerts` via
    `JdbcSink` with the complete `String[]` array of transaction IDs.

- flink-job/src/main/java/com/mule/detector/function/PassThroughDetector.java:
  * Extends `KeyedProcessFunction<String, Transaction, Alert>`.
  * Maintains state per UPI account:
    - `firstIncomingTimestampState` (`ValueState<Long>`): Timestamp of first inflow.
    - `lastActivityTimestampState` (`ValueState<Long>`): Timestamp of latest event.
    - `hopTxnIdsState` (`ListState<String>`): List of all transaction IDs involved.
    - `cumulativeAmountState` (`ValueState<Double>`): Cumulative money volume.
  * When an INCOMING event arrives:
    Checks if previous window has expired (> 15s). If expired, starts a fresh window.
    Appends the incoming transaction ID to `hopTxnIdsState`.
  * When an OUTGOING event arrives:
    Calculates `timeDiff = currentTxnTime - firstIncomingTimestamp`.
    If `0 <= timeDiff <= 15000` (15 seconds):
      Appends the outgoing transaction ID to `hopTxnIdsState`.
      Extracts all accumulated IDs in chronological order without duplicates.
      Emits an `Alert` containing the account ID, cumulative amount, detection 
      timestamp, and the complete `List<String> allTxnIds` sequence.
      Does NOT immediately clear the state, allowing additional downstream or 
      layering hops (Hop 3, 4, 5) to append to the chain.
      Registers a processing-time timer (`ctx.timerService().registerProcessingTimeTimer`)
      to safely purge the window state after 15 seconds of inactivity.

- flink-job/src/main/java/com/mule/detector/model/Transaction.java:
  * POJO modeling the transaction payload. Supports Jackson JSON serialization.
  * Robust `getTimestampMillis()` parser handling ISO-8601 UTC and local formats.
  * Contains `accountId` and `direction` ("INCOMING" or "OUTGOING") fields.

- flink-job/src/main/java/com/mule/detector/model/Alert.java:
  * POJO modeling the fraud alert with fields: `alertId`, `alertType`, `accountId`,
    `amount`, `detectedAt`, and `List<String> txnIds`.

- flink-job/src/main/java/com/mule/detector/deserializer/TransactionDeserializationSchema.java:
  * Implements `DeserializationSchema<Transaction>`. Converts raw Kafka byte arrays
    into `Transaction` Java objects using Jackson `ObjectMapper`.

4.3 COLUMNAR DATABASE: clickhouse/
--------------------------------------------------------------------------------
Files:
- clickhouse/schema.sql:
  * Executed automatically on container initialization via `/docker-entrypoint-initdb.d/`.
  * Creates database `default`.
  * Creates table `default.raw_transactions`:
    - Columns: transaction_id, timestamp, sender_name, sender_vpa, receiver_name,
      receiver_vpa, amount, status, bank_code, location.
    - Engine: `MergeTree()`.
    - Partition: `toYYYYMMDD(timestamp)`.
    - Primary Order Key: `(sender_vpa, timestamp)`.
    - Index: `INDEX idx_txn_id transaction_id TYPE bloom_filter() GRANULARITY 1`.
      The bloom filter index enables instant sub-millisecond lookups by transaction_id.
  * Creates table `default.fraud_alerts`:
    - Columns: alert_id UUID, alert_type String, account_id String, amount Float64,
      detected_at DateTime64(3, 'UTC'), txn_ids Array(String).
    - Engine: `ReplacingMergeTree()`.
    - Partition: `toYYYYMMDD(detected_at)`.
    - Primary Order Key: `(account_id, detected_at)`.

4.4 BACKEND API: alert-api/
--------------------------------------------------------------------------------
Files:
- alert-api/main.py:
  * Built with FastAPI and Uvicorn. Enables CORS for frontend integration.
  * Connects to ClickHouse host `clickhouse:8123` via `clickhouse_connect`.
  * Endpoints provided:
    1. `GET /health`:
       Returns `{"status": "ok", "clickhouse_connected": true}`.
    2. `GET /stats`:
       Executes `SELECT count(), coalesce(sum(amount), 0) FROM raw_transactions`.
       Returns real-time aggregate count and volume for the UI telemetry cards.
    3. `GET /transactions?limit=50`:
       Queries `raw_transactions` ordered by `timestamp DESC` for the live feed.
    4. `GET /alerts?limit=50`:
       Queries `fraud_alerts` ordered by `detected_at DESC` for the alert watchlist.
    5. `GET /alerts/{alert_id}`:
       Bidirectional Graph Hop Traversal Algorithm:
       - Retrieves `txn_ids` from `fraud_alerts`.
       - Queries `raw_transactions WHERE transaction_id IN (...)`.
       - Expands FORWARD up to 5 hops: Finds subsequent transfers where 
         `sender_vpa == previous_receiver_vpa` within Delta t <= 15s.
       - Expands BACKWARD up to 5 hops: Finds prior transfers where 
         `receiver_vpa == earliest_sender_vpa` within Delta t <= 15s.
       - Returns the full chronologically indexed chain: Hop 1 -> Hop 2 -> Hop 3 -> Hop 4 -> Hop 5.

- alert-api/Dockerfile:
  * Base image: `python:3.10-slim`.
  * Exposes port 8000 and runs `uvicorn main:app --host 0.0.0.0 --port 8000`.

4.6 INFRASTRUCTURE & AUTOMATION: root/
--------------------------------------------------------------------------------
Files:
- docker-compose.yml:
  * Defines 7 services on network `upi-net`:
    1. `kafka`: `apache/kafka:3.7.0` (KRaft broker on port 9092, internal only).
    2. `clickhouse`: `clickhouse/clickhouse-server:24.3` (OLAP database on 8123, 9000, internal only).
    3. `jobmanager`: `flink:1.18-scala_2.12-java11` (Flink cluster manager on 8081, internal only).
    4. `taskmanager`: `flink:1.18-scala_2.12-java11` (4 task execution slots, internal only).
    5. `producer`: Custom Python container running `simulator.py` (internal only).
    6. `alert-api`: Custom FastAPI container on port 8000 (internal only).
    7. `frontend`: Custom Node/Vite container on port 5173 (SOLE EXPOSED PORT).

- start.ps1:
  * Automated 5-stage deployment script:
    Stage 1: Validates Docker Desktop daemon connectivity.
    Stage 2: Compiles the Flink Java fat JAR using a containerized Maven image 
             (`maven:3.8.8-eclipse-temurin-11 mvn clean package`), completely 
             eliminating the need to have Maven or Java installed on the host.
    Stage 3: Cleans old containers (`docker compose down --remove-orphans`) and 
             launches all 7 services in background (`docker compose up -d --build`).
    Stage 4: Polls ClickHouse HTTP ping and Flink TaskManager slot registration.
    Stage 5: Submits the compiled Flink fat JAR to JobManager via `docker exec`.

6. HOW TO RUN AND OPERATE THE PROJECT
================================================================================

1. Ensure Docker Desktop is running on Windows.
2. Open PowerShell in the project directory:
   cd D:\Mini

3. Run the automated startup script:
   .\start.ps1

4. Once the script prints "ALL SYSTEMS GO!", open your browser:
   - Dashboard: http://localhost:5173
   - Flink UI:  http://localhost:8081
   - API Docs:  http://localhost:8000/docs

5. Inspecting live services:
   # View live transaction simulation output:
   docker logs -f producer

   # View Flink fraud alert detection warnings:
   docker logs -f taskmanager

   # View FastAPI queries and hop chain expansion:
   docker logs -f alert-api

6. Direct SQL verification in ClickHouse:
   docker exec -it clickhouse clickhouse-client --query "SELECT alert_id, account_id, amount, length(txn_ids) AS hops, txn_ids FROM default.fraud_alerts ORDER BY detected_at DESC LIMIT 5 FORMAT Pretty;"

7. Shutting down the cluster:
   docker compose down
